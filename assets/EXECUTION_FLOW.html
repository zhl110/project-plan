② 三种建档模式（决策②③的分支）

🟢 创建模式 全新项目

  1. 项目根放 AGENTS.md — 仅当根不存在时创建；已存在则跳过并报告路径，绝不覆盖。
  2. 根下建 .plan/，放入 PRD.md / PLAN.md / progress.md（从 templates 复制骨架）。
  3. 与用户确认需求后填 PRD（背景/目标/需求/验收）。
  4. 📐 文件布局规划（详见 file-layout.md）：动手前想清目录分布与产物落点，按复杂度弹性（S 一句话 / M 列核心 / L·XL 完整表）；B 层快照进 PLAN、随结构演化刷新，布局是镜子不是笼子。
  5. 填 PLAN（阶段/步骤/决策/验证/风险 + 文件布局段），并跑一次「预执行自检清单」。
  6. 填 progress 的元信息 + 上下文压缩。
  7. 展示计划，用户确认后再执行。

🟠 补录模式 已开工缺档案

  1. 触发：项目根有代码 / 产物 / git 历史，但无档案；或档案是空模板。档案是反向侦查出来的，不是模板填出来的。
  2. 派侦察兵子 agent（只读）盘点磁盘证据：git log、目录结构、依赖清单、文档 → 证据清单 + L1/L3 分类。
  3. 信息源分级：L1 磁盘证据可直接写；L2 agent 已知（标「来自对话」）；L3 推不出标「待确认」，禁编造。
  4. PLAN 当前阶段标真实状态（回溯标记）；progress 首条写「回溯建档」，不伪造历史。
  5. 完成后必过哨兵核验 → 展示差异清单待用户确认。

🔵 跟踪模式 已有档案

  1. 读 AGENTS.md → 读 .plan/PLAN.md → 读 .plan/progress.md（含上下文压缩与交接上下文）。
  2. 从交接上下文的断点继续。
  3. 每完成一个动作/阶段，按纪律更新 PLAN 状态与 progress。

已有档案则不重建，直接接手，从 progress 的「交接上下文」知道做到哪。哨兵不强制，改哪补哪、对照合格标准自检。

🛡️ 哨兵核验（创建 / 补录建档后必过）：派独立只读子 agent 按各文件「合格标准」核验——①结构与必填段齐全 ②状态真实（PLAN 当前阶段 vs 项目现实）③无编造（progress 无伪造历史；标 L1 的内容抽查与磁盘对得上）④红线合规。未达标 → 列清单补齐 → 复检（最多 2 轮，仍未过停手交用户裁决），通过才算建档完成；结论（PASS / 未达标清单）记入 progress 留痕；通过后才向用户展示确认。主 agent 自查自评不算数——自己建的档自己验必放水，与 DARWIN 自评偏差同源。S 级项目豁免（≤3 文件，对照合格标准自检即可）。哨兵提示词须附合格标准原文或让子 agent 自读 generate-files.md。

🧭 文件集裁剪（项目性质评估结论）：建档前先判定项目类型，决定生成哪些文件，不无脑四件套。

  • 交付型 delivery：有明确定义产物 + 验收 + 可收敛路径 → 生成四件套（AGENTS + PRD + PLAN + progress）。
  • 运营型 operation：长期、开放式、无单一交付物（如长期任务项目）→ 仅 AGENTS.md + .plan/progress.md，不生成 PRD/PLAN。
  • 类型可单向升级：运营型后期长出交付需求，执行 scaffold.py --type delivery 只补 PRD/PLAN，不覆盖已有 AGENTS/progress。

③ 复杂度分级（决定 PLAN 粒度）

级别标准PLAN 写法
S≤3 文件，单领域，无外部依赖直接列步骤，不必拆阶段
M4–15 文件，1–2 领域，有依赖按阶段拆，每阶段列步骤
L16+ 文件，多领域/多模块9 阶段全走，每阶段详细子步骤
XL跨系统、长期L + 每阶段独立评审门禁

判断不准时取更高一级。S 级可略过预执行自检；M/L/XL 必须全过。

④ 预执行自检清单（PLAN 定稿前过一遍）

建档后、动手前按复杂度跑自检，FAIL 项修完再执行。任一 CRITICAL（安全违规 / 无备份 / 新代码不可达）未解 → 不执行。

  • 完整性：目标可测、阶段有序不重叠、每阶段有验收标准、无 TBD 阻塞项
  • 可行性：时长与工作量匹配（S≤2h / M≤6h / L≤16h / XL>16h）、依赖与假设已写明、用现成工具不重造
  • 风险：无 AGENTS.md 安全违规（rm -rf / --force / 泄密）、无单点阻塞、改前已备份
  • 修改安全（改既有文件时必查）：原文件已备份、有回滚路径、调用方已同步、有验证步骤
  • 死代码（加新代码时必查）：新函数/模块能追溯到调用点、配置项已接进 loader、路由/CLI 已注册
  • 可验证：每阶段有显式 pass/fail 准则、有冒烟测试、回滚可验证
  • 依赖：步骤顺序正确（无步骤读后步产物）、并行分支真独立、无同一文件并发冲突
  • 对齐：解决的是用户真实意图、尊重 AGENTS.md、不超出既定目标（scope creep）
  • 文档：API/配置变更有记录、用户可见变更有说明

⑤ 生命周期阶段模型（PLAN 的阶段词汇表）

阶段裁剪

  • S 级：①→⑤→⑥→⑨（精简）
  • M 级：全流程精简
  • L / XL：全流程 + 每阶段详细子步骤与评审门禁

交叉关注点（贯穿全程）

  • 每阶段对应一次 git commit
  • 改关键文件前备份
  • 踩坑即记入项目笔记
  • 进度可见；中断在 progress 标断点

⑥ 变更同步（PRD ↔ PLAN ↔ progress）

执行循环中的同步规则：任一处变更，按规则联动另两端，不允许只改一处。

  1. PRD 变了 → 先改 PRD 并在其「变更记录」留痕（改了什么 + 为什么）。
  2. PLAN 跟着变（顺流）：新增需求→PLAN 加任务；删除需求→任务标 cancelled（不物理删）；验收变→PLAN 验证表同步；约束变→关键决策同步。
  3. progress 必追加：每次变更在 progress 写「变更：PRD 改 X；PLAN 相应 Y；原因 Z」。
  4. 反向也管：执行中发现 PRD 不可行/遗漏，先回头改 PRD 再同步 PLAN，不允许只改 PLAN 让 PRD 与实际脱节（PRD 是单一真相源）。
  5. 三端可对照：PRD 变更记录 / PLAN 变更记录 / progress 流水，靠日期+简述互对。

progress 的四大块（交接文档核心）

压缩 任务上下文压缩

  • 用户偏好
  • 整体架构（相关部分）
  • 关键文件索引
  • 已确认的决策
  • 环境/依赖

交接 交接上下文

  • 当前断点
  • 已完成的内容
  • 未完成的内容
  • 关键发现/注意事项
  • 下一步建议

动态 动态调整

  • 新增标 [新增 时刻]
  • 删除标 [已删除 时刻] 原因
  • 修改标 [已修改 时刻] 原因
  • 不物理删，留历史

日志 变更日志

  • | 时间 | 操作 | 说明 |
  • 创建 / 更新 / 新增
  • 删除 / 暂停 / 恢复
  • 变更（PRD↔PLAN）

⑦ 执行循环详图（Agentic Loop）

总图里的「执行循环」展开后是一个 agent 化的回路：规划 → 执行 → 遇问题则解决（失败/不安全则撤销回滚）→ 沉淀经验写回 AGENTS.md → 方案调整则回写 PRD/Plan → 从待施任务取下一个。下方节点与 SKILL 规则一一对应。

执行 hub 问题、解决 撤销 / 回滚 规则写回 Agents.md 修改 PRD/Plan 待施任务

⚙️ 执行每完成一个动作即更新 PLAN 状态 + 追加 progress（纪律 #3/#4）

⑧ 关键纪律（贯穿全程）

#纪律要点
1AGENTS.md 非破坏性根已存在则跳过，绝不静默覆盖
2开工先读上下文跟踪模式：先读 AGENTS → PLAN → progress，从断点继续；项目根未确认前禁读任何项目文件（先确认再读）
3每轮必追加 progress每个动作/阶段后追加一条；纯问答也补「无动作」
4状态禁造假PLAN 完成态必须真实，没做完不能标完成
5下一步只填一个动作PLAN 的「下一步」永远只有一个待执行动作
6最后更新必刷新PLAN 每次变更更新「最后更新」时间戳
7变更必同步PRD/PLAN/progress 任一处变，联动另两端
8AGENTS.md 是活规则库执行中持续写回；优先追加、不删用户规则、更新规则直接改/删条文不保留「已弃用」标注、不补变更留痕（见红线 #18）
9.plan/ 只放四件套代码/产物/临时文件进项目其他目录，不塞进 .plan/
10收工约定PLAN 置完成、末条 progress 标 [状态: 收工]；.plan/ 可保留或归档
11交接必填上下文暂停/换人前，progress 的交接上下文必须完整
12提交守纪律见 references/commit-discipline.md：原子提交、约定式、不强制推共享分支、合并前 rebase
13验收默认不通过见 references/review-gates.md：产物/阶段须有证据才算过，首版允许 2–3 轮修订
14AGENTS.md 渐进式披露规则跨多主题(≥5)或过长(>~120行)拆 AGENTS.d/<topic>.md，AGENTS.md 留索引；按需加载、写回对应子文件
15补录必溯源补录内容标注信息源（磁盘证据/agent 已知/待确认）；progress 不伪造历史；禁写"应该/大概"
16哨兵门禁创建/补录建档后必过独立只读子 agent 核验；未达标补齐复检；自查自评不算数
17布局是镜子不是笼子文件布局分 A 层稳定规则(进 AGENTS.md)与 B 层可变快照(进 PLAN 架构段，大型项目可 AGENTS.d/layout.md)；B 层随结构演化正常刷新，更新快照不算破规则；须镜像现实(对标红线#4)

# 变更同步（PRD ↔ PLAN ↔ progress）

> 本文件在**修改需求 / 计划时**加载。PRD/PLAN/progress 任一处变更，按规则联动另一端，不允许只改一处（单一真相源原则）。

1. **PRD 变了** → 先改 PRD 并在其"变更记录"留痕（改了什么 + 为什么）。
2. **PLAN 跟着变（顺流）**：新增需求→PLAN 加任务；删除需求→任务标 `cancelled`（不物理删）；验收变→PLAN 验证表同步；约束变→关键决策同步。
3. **progress 必追加**：每次变更在 progress 写"变更：PRD 改 X；PLAN 相应 Y；原因 Z"。
4. **反向也管**：执行中发现 PRD 不可行 / 遗漏，先回头改 PRD 再同步 PLAN，**不允许只改 PLAN 让 PRD 与实际脱节**（PRD 是单一真相源）。
5. **三端可对照**：PRD 变更记录 / PLAN 变更记录 / progress 流水，靠日期 + 简述互对。
6. **「下一步」两处一致**：交付型 PLAN「下一步」与 progress「下一步/待办」镜像段须同步刷新——任一处变更，另一处随即改，不漂移；运营型无 PLAN，progress「下一步/待办」即唯一真相源（无镜像对象）。

## 进度文件的对应写法

- 变更条目写入 progress「变更日志」表（列定义见 `progress-spec.md`：`| 时间 | 操作 | 说明 |`）——其中「操作」填「变更」、「说明」填「PRD 改 X；PLAN 相应 Y；原因 Z」。即下表与本文件是同一张表，不要当成两种格式：
  `| YYYY-MM-DD | 变更 | PRD 改 X；PLAN 相应 Y；原因 Z |`
- 会话流水同步追加一条动作记录（动作 → 为什么 → 涉及文件 → 验证 → 错误）。
- 动态调整（增删改步骤）必留痕：新增标 `[新增 时刻]`、删除标 `[已删除 时刻] 原因`、修改标 `[已修改 时刻] 原因`——不物理删，留历史。

# 范例：完整填好的四件套（参考样例）

本文件是一个**真实可模仿**的样例，展示四个文件各自填到"合格标准"长什么样。项目设定为「个人记账 Web 应用」。agent 在写每个文件前，对照本样例的结构与粒度即可。

> 注意：本文件是 `references/`，按需载入上下文参考；它**不是**要复制进用户项目的产物。

---

## 1. AGENTS.md（落项目根）

```markdown
# 项目规则：个人记账 Web 应用

## 项目目标
一个本地优先、单人使用的记账 Web 应用：录入收支、按分类/月份统计、导出 CSV。

## 技术栈
- 前端：原生 HTML + CSS + 少量 JS（不引框架）
- 存储：浏览器 localStorage
- 运行：纯静态，无需后端

## 目录结构约定
- `index.html` 入口
- `app.js` 逻辑
- `styles.css` 样式
- `data/` 仅放导出样例，不存真实数据

## 通用工作纪律（初始种子，后续由 agent 与用户共同优化）
1. 不可逆操作（清库/覆盖）先问用户。
2. 改动前先读本项目规则与现有代码。
3. 长任务每阶段向用户汇报。
4. 删除文件前通读全文。
5. 不确定时先问关键问题。

## 本项目特有规则
- 金额一律以「分」为整数存储，展示时除以 100，避免浮点误差。
- 分类固定为：餐饮/交通/住房/娱乐/其他，不开放自定义。

## 变更记录
- 2026-10-27 user：创建
- 2026-10-27 agent：补充「金额以分存储」规则（执行中沉淀）
```

## 2. PRD.md（落 .plan/，仅交付型）

```markdown
# 产品需求文档（PRD）：个人记账 Web 应用

## 问题陈述
用户用 Excel 记账繁琐、易漏、无离线随手记的入口，想要一个打开即用的网页，离线也能记。

## 目标用户
单人、非技术背景、有基础记账需求。

## 目标与成功指标
| 指标 | 基线 | 目标 | 窗口 |
|------|------|------|------|
| 单笔记账耗时 | 手动 Excel ~2min | < 20s | 首版 |
| 离线可用 | 否 | 是（纯静态） | 首版 |
| 月度汇总准确率 | 人工易错 | 100% | 首版 |

## 核心需求
| 编号 | 描述 | 优先级 |
|------|------|--------|
| R1 | 录入一笔收支（金额、分类、日期、备注） | P0 |
| R2 | 按月份 + 分类查看汇总 | P0 |
| R3 | 编辑 / 删除已录入记录 | P1 |
| R4 | 导出当月 CSV | P2 |

## 非目标
- 不做多用户 / 云同步
- 不做预算告警、图表美化
- 不做记账规则 AI 建议

## 验收标准（Given-When-Then）
- **AC1 持久化**：Given 用户录入 R1 后刷新页面，When 重新打开，Then 数据仍在（localStorage 持久化）。
- **AC2 汇总**：Given 选定某月，When 查看汇总，Then 该月各类总额正确显示。
- **AC3 删除**：Given 删除一条记录，When 重算汇总，Then 数字即时更新。
- **AC4 导出**：Given 点导出，When 打开 CSV，Then Excel 可直接打开且字段含日期/分类/金额/备注。

## 约束与假设
- 假设用户只在单一浏览器使用，不做跨设备。
- 约束：单文件体积 < 50KB，不引第三方库。

## 风险
| 风险 | 可能性 | 影响 | 缓解 |
|------|--------|------|------|
| 隐私模式 localStorage 受限 | 中 | 中 | 首屏提示用户开启持久化 |
| 超大金额浮点精度 | 低 | 高 | 全程以「分」整数存储 |

## 变更记录
- 2026-10-27 创建
- 2026-10-27 用户新增 R4（导出 CSV），验收 AC4 同步
```

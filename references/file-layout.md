# 文件布局规划：动手前想清楚，演化中保持同步

> 本文件在**建档的「创建模式」与「补录模式」**加载。专门解决：动手写代码 / 产出前先想清"项目由哪些文件 / 目录构成、产物落哪"，并让这份布局**随项目演化持续刷新**——避开"随手建文件随便放"与"布局写死后和现实脱节"两个极端。

## 为什么单独讲（矛盾根源）

一个项目该有哪些块、哪些文件，从来不是凭空定的——它**基于我们做这个项目的一开始想法 / 出发点**，随项目目标、PRD、步骤的推进而生成，也**必然随这些东西一起变**。

如果把"文件布局"当成一份**不可变规则**写死，那么每次项目演化（新想法 → 产物改变 → 增删目录）都是在"破坏已承诺的规则"——这就是破坏性矛盾的根源：**把「随项目演化的可变快照」错当成了「稳定规则」来管理。**

> 一句话：**档案结构（四件套 + 布局段）是以项目为中心的、随项目而生的，不是普适死模板。** 它该镜像项目现实，而不是反过来要求项目迁就它。

## 解法：规则与可变快照分离（mirror-not-law）

核心原则：**布局文档是现实的镜子，不是笼子。文档跟随现实，现实不跟随文档。**

| 层 | 性质 | 内容 | 变了算什么 |
|----|------|------|-----------|
| **A 层·稳定规则**（进 AGENTS.md） | 真规则 | 命名约定、「不在源码树随手建临时文件」、「新产物必须先登记进布局再创建」 | 违反 = 坏 |
| **B 层·可变快照**（进 PLAN 架构段 / 大型项目 `AGENTS.d/layout.md`） | 随项目演化的快照 | 当前目录树、模块切分、产物落点表 | 改变 = 正常，须刷新 |
| **C 层·变更事件**（正常循环动作，非违规） | 同"追加 progress" | "结构变了 → 刷新快照" | 与进度回写同地位 |

**消除矛盾的机制**：更新一个*快照*不算破*规则*。skill 的一致性纪律反而被保留——布局段被**显式归类为可变状态 + 定义了刷新节奏**，不存在"对已承诺约束的漂移"，约束本身变成"快照须与现实同步"（对标红线 #4 状态禁造假 → 布局禁造假）。

## 弹性强度（按复杂度，复用 S/M/L/XL 分级）

| 复杂度 | 布局规划强度 | B 层快照形态 |
|--------|-------------|-------------|
| **S**（≤3 文件） | AGENTS.md 一句话目录约定即可，不强制表格 | 一句话 |
| **M** | 列核心目录 + 关键产物落点 | 简表 |
| **L/XL** | 完整「区块划分 + 目录结构 + 产物落点表 + 命名约定 + 临时文件隔离区」 | 完整表，可渐进式披露到 `AGENTS.d/layout.md` |

> 不做一刀切死模板：小项目一句话够，大项目才需详细落点表。

## 创建模式：何时做、怎么做

时机：**PRD 需求确认后、PLAN 动手前**（属「② 架构设计」阶段的可交付产出）。

1. 按复杂度选强度（上表）。
2. 产出 B 层快照：区块 / 模块划分（按功能 / 关注点切，不按文件类型堆）、目录结构、产物落点表 `| 产物 | 路径 | 归属区块 | 形态 |`。
3. 沉淀 A 层规则：命名约定、临时文件隔离区（不进源码树）。
4. 落点：B 层写进 PLAN「文件布局 / 产物落点」段（大型项目渐进式披露到 `AGENTS.d/layout.md`）；A 层写进 AGENTS.md 工作纪律。
5. 标「最后核对」时间戳。

## 补录模式：反向推出已有布局

侦察兵子 agent 盘点时，除现有证据外，须**反向推导当前文件布局**：
- 列实际目录树与模块归属。
- 标注「是否散乱 / 随手建」：无规划、产物与目录名不符、临时文件混进源码树 → 给整理建议（列入 AGENTS.md 的「待办 / 改进项」段——可选的中长期改进清单，**不阻断执行循环**；循环取下一个动作一律以 progress「下一步」为准，见 runtime-loop）。
- 推导结果作为 B 层快照写入 PLAN；散乱项按 L2/L3 处理。

## 演化中的刷新（变更事件 C 层）

执行循环中，动作导致结构变化（新增 / 删除 / 移动目录或顶层文件），**按正常步骤刷新 B 层快照**，不是破戒：
- 在 `runtime-loop` 步骤 8「更新 PLAN 状态 + 追加 progress」时，若本次动作改变了结构，一并更新 PLAN「文件布局」段 + 「最后核对」时间戳。
- 新产物不在布局内：**先改布局再放**（A 层规则：先登记再创建），不事后补理由。
- 复用 `change-sync`：布局是 PLAN 字段，PLAN 变即联动（progress 记「结构调整」条）。

## 哨兵校验（延伸红线 #16）

建档 / 补录的哨兵核验增加一项：**实际目录树 ≈ 文档布局**。
- 不符 → 更新文档匹配现实（doc follows reality）；若现实才是错的（随手建脏文件），列进待清理清单交用户。
- 不靠 agent 自报"布局对得上"。

## 合格标准（B 层快照自检）

- S 级：AGENTS.md 目录约定非空、可指认源码 / 产物位置。
- M 级：核心目录列出 + 关键产物有落点。
- L/XL 级：①区块按关注点切 ②目录结构完整 ③产物落点表覆盖主要产物 ④命名约定明确 ⑤临时文件隔离区声明 ⑥「最后核对」时间戳有值 ⑦无"临时文件混进源码树"反例。

## 约束（禁项，违反即不合格）

- 不在源码树随手建临时文件（A 层规则，真规则）。
- 新产物不先登记进布局就创建（A 层规则）。
- B 层快照长期不刷新、与 reality 明显脱节（对标红线 #4）。

# 规划结构：复杂度分级 · 预执行自检 · 生命周期阶段

> 本文件在**规划定稿 / 动手前**加载。用于决定 PLAN 粒度、过一遍自检、选阶段词汇。

## 复杂度分级（决定 PLAN 粒度）

| 级别 | 标准 | PLAN 写法 |
|------|------|-----------|
| **S** | ≤3 文件，单领域，无外部依赖 | 直接列步骤，不必拆阶段 |
| **M** | 4-15 文件，1-2 领域，有依赖 | 按阶段拆，每阶段列步骤 |
| **L** | 16+ 文件，多领域 / 多模块 | 9 阶段全走，每阶段详细子步骤 |
| **XL** | 跨系统、长期 | L + 每阶段独立评审门禁 |

判断不准时取更高一级。

## 预执行自检清单（PLAN 定稿前过一遍）

建档后、动手前，按复杂度跑自检，FAIL 项修完再执行：

- [ ] **完整性**：目标可测、阶段有序不重叠、每阶段有验收标准、无 TBD 阻塞项
- [ ] **可行性**：时长与工作量匹配（S≤2h/M≤6h/L≤16h/XL>16h）、依赖与假设已写明、用现成工具不重造
- [ ] **风险**：无 AGENTS.md 安全违规（rm -rf/--force/泄密）、无单点阻塞、改前已备份
- [ ] **修改安全**（改既有文件时必查）：原文件已备份、有回滚路径、调用方已同步、有验证步骤
- [ ] **死代码**（加新代码时必查）：新函数 / 模块能追溯到调用点、配置项已接进 loader、路由 / CLI 已注册
- [ ] **可验证**：每阶段有显式 pass/fail 准则、有冒烟测试、回滚可验证
- [ ] **依赖**：步骤顺序正确（无步骤读后步产物）、并行分支真独立、无同一文件并发冲突
- [ ] **对齐**：解决的是用户真实意图、尊重 AGENTS.md、不超出既定目标（scope creep）
- [ ] **文档**：API / 配置变更有记录、用户可见变更有说明

S 级可略过；M/L/XL 必须全过。任一 CRITICAL（安全违规 / 无备份 / 新代码不可达）未解 → 不执行。

## 生命周期阶段模型（PLAN 的阶段词汇表）

PLAN 的阶段从以下 9 阶段取用，保证跨项目一致：

```
① 需求定义 → ② 架构设计 → ③ 任务规划 → ④ 环境搭建
→ ⑤ 编码实现 → ⑥ 审查精修（审→修→验闭环）→ ⑦ 安全审计
→ ⑧ 部署上线（预检→发布→验证→回滚）→ ⑨ 交接维护
```

- S 级：①→⑤→⑥→⑨（精简）
- M 级：全流程精简
- L/XL 级：全流程 + 每阶段详细子步骤与评审门禁

**回溯项目的阶段判定（补录模式用）**：给已开工的项目补 PLAN 时，「当前阶段」按项目现实落在词表上——用 git log / 交付物状态判定已完成到哪一阶段（该阶段标 complete 并注明「回溯标记」），现实所处阶段标 in_progress，其后阶段一律 pending。**禁止默认从 ① 起步**——那是状态造假。

交叉关注点（贯穿全程）：每阶段对应一次 git commit；改关键文件前备份；踩坑即记入项目笔记；进度可见；中途中断在 progress 标断点。

# 进度与交接规范

> 本文件在**写 / 更新 progress.md 时**加载。progress.md 不止是流水账，更是**交接文档**——任何接手 Agent 打开它（配合 PLAN.md）应在 30 秒内懂：做到哪了、为什么、下一步从哪干。

## 1. 任务上下文压缩（建档时写入，省去接手 Agent 翻项目）

| 区块 | 写什么 |
|------|--------|
| 用户偏好 | 本次任务的命名 / 风格 / 技术选型 / 工具偏好 |
| 整体架构（相关部分） | 仅与任务相关的模块结构与文件关系 |
| 关键文件索引 | 涉及文件列表 + 每文件一句话说明 |
| 已确认的决策 | 做了什么 + 为什么 + 谁确认 |
| 环境 / 依赖 | 运行所需环境、依赖版本、特殊配置 |

随执行发现新信息持续补充；新建项目允许基于需求预填要点，架构 / 文件索引可标"待项目产出后补充"，但不得整段留占位不写。

## 2. 交接上下文（每次暂停必填，结构对齐 handoff-templates）

假设接手者一无所知，当成写给陌生人的说明书（与 `generate-files.md` progress 段一致）：
- **From / To**：本 Agent（或"用户本人"）→ 接手方（下个 Agent / 未来的自己 / 用户）
- **当前阶段 + 断点**：所处阶段（交付型取自 PLAN 阶段词表）+ 停在第几步 / 哪子任务
- **相关文件**：`路径 — 含什么`（改动 / 产出 / 待读）
- **依赖 / 约束**：本工作依赖什么就绪、技术 / 时间 / 资源约束
- **已完成的内容**：具体产出物
- **未完成的内容**：按步骤列
- **关键发现 / 注意事项**：特殊逻辑、环境坑、踩过的雷
- **下一步建议**：明确起点（与 PLAN「下一步」一致）

> 交付型项目：阶段切换前还应过 `review-gates.md` 的阶段门禁，门禁证据随交接上下文一并留痕。

## 3. 会话流水（每次动作追加）

格式：`动作 → 为什么 → 涉及文件（修改/新增/删除 + 路径）→ 验证 → 错误`。
- 序号 = 当前最大 N + 1；同一天内连续动作可并入同一会话段。
- 纯问答也补一条：`- 无动作：回答了用户关于 X 的疑问`。
- 涉及文件按修改 / 新增 / 删除三类列出路径，便于接手者快速定位改动。

## 4. 动态调整（增删改步骤必留痕）

新增标 `[新增 时刻]`、删除标 `[已删除 时刻] 原因`、修改标 `[已修改 时刻] 原因`——不物理删，留历史。

## 5. 变更日志

`| 时间 | 操作 | 说明 |`，谁在何时做了什么一目了然。操作类型：创建 / 更新 / 新增 / 删除 / 暂停 / 恢复 / 变更（PRD 改 X；PLAN 相应 Y；原因 Z）。

## 红线

- 只追加不回改历史条目。
- 不写背景 / 规则（那是 PRD / AGENTS）。
- `.plan/` 只放四件套，不得塞代码 / 产物。

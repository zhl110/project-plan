# 运行时执行循环

> 本文件在**执行任务阶段**加载。建档或接手后进入迭代回路，循环至收工。图 `assets/EXECUTION_FLOW.html` 的「执行循环详图」据此绘制，互为镜像。

建档或接手后进入迭代回路，循环至收工。每轮按序：

> **运营型（无 PRD/PLAN）简化循环**：取任务来自 progress「下一步」（运营型唯一真相源，无 PLAN）→ 执行 → 按 AGENTS 约定 / 用户标准验证 → 沉淀规则写回 AGENTS → 追加 progress；跳过本循环第 7 步（回写 PRD/Plan）。其余纪律不变。

> **AGENTS.md 规则按需加载**：若项目启用「索引 + `AGENTS.d/` 子文件」模式，开工只读取 AGENTS.md 索引（薄入口）；执行某任务时，仅加载该任务触及的主题子文件（如改 CI 才读 `AGENTS.d/ci.md`），不整篇读入所有规则。写回规则追加到对应主题子文件。

1. **取任务**：交付型从 PLAN「下一步」（单动作）或当前阶段待办取一个动作；运营型从 progress「下一步」取（运营型无 PLAN，progress「下一步」即唯一真相源）；无待办则进收工。
2. **执行**：只做这一个动作，不一次铺开多个。
3. **验证**：交付型对照 PLAN 验证结果表 / 验收标准判成败，并按 `review-gates.md` 的"默认不通过 + 须有证据"精神出裁决，不靠自报；运营型按 AGENTS 约定 / 用户标准验证；纯问答也补「无动作」进度。
4. **遇问题 → 解决 / 收要求**：踩坑、报错、解法记入 PLAN「错误记录表」「验证结果表」；影响后续则同步 AGENTS.md 注意事项。用户在执行中**新提出的明确要求**，若影响范围 / 验收，按步骤 7 回写 PRD（不带着脱节的计划继续）。
5. **解决失败或不安全 → 撤销 / 回滚**：产出错误结果或触发安全违规时，回退到上一稳定态——动用修改安全纪律的备份与回滚路径，不带着错误继续。
6. **沉淀规则 → 写回 AGENTS.md**：执行中确认出的项目约定 / 踩坑 / 约束，按 AGENTS.md 维护纪律持续写回（活规则库，优先追加、不删用户已写规则）。
7. **方案须调整 → 回写 PRD/Plan**（仅交付型）：原 PRD/Plan 不成立或需变更，按 `change-sync.md` 回写并联动 progress，不带着脱节的计划继续。运营型无 PRD/Plan，跳过本步。
8. **更新状态 + 写进度**：动作完成即更新 PLAN 状态、「下一步」、最后更新，并追加一条 progress 流水（动作 → 为什么 → 涉及文件 → 验证 → 错误）。**若本次动作改变了项目结构**（新增 / 删除 / 移动目录或顶层文件），一并刷新 PLAN「文件布局」段 + 「最后核对」时间戳（布局是 B 层可变快照，随结构演化正常刷新，详见 `file-layout.md`；新产物先登记再放）。**若刚完成的是一个阶段**，先过 `review-gates.md` 的阶段门禁（门禁不通过则退回补，不切阶段），通过后在 progress 写一段「阶段小结」：本阶段门禁结果、遇到的问题与解决、用户新增要求、已沉淀进 AGENTS.md 的新规则条目——这就是"总结更新"。运营型无阶段门禁，跳过。
9. **参考**：遇不确定先看 `assets/` 模板与本项目 AGENTS/PRD/PLAN 历史经验，不凭空起炉灶；写每个文件前对照 `references/example-filled.md` 的样例。
10. 回到第 1 步取下一个任务。

## 异常场景处理（遇以下情况按表处理，不裸奔）

执行循环中任何一步都可能偏离预期，按表处置，杜绝「带着错误 / 脱节信息继续」：

| 场景 | 处理方式 |
|------|----------|
| 需求仍模糊，用户说不清要什么 | 先澄清目标 / 范围 / 验收 / 不做的边界再建档，不凭空生成 PRD |
| 执行中用户新提要求影响范围或验收 | 按步骤 7 回写 PRD，不带着脱节的计划继续 |
| 某任务阻塞（依赖未就绪 / 卡死） | 交付型在 PLAN 该任务标 `BLOCKED`；运营型在 progress 待办标阻塞并先做不依赖的部分 |
| 审查 / 验证发现严重问题 | 退回上一稳定阶段修复，修复后重走验证闭环，不带着病前进 |
| 阶段门禁 FAIL / 验收不通过 | 按 `review-gates.md` 出裁决 + 待修项，退回本阶段补，最多 3 轮；第 3 轮仍 FAIL 走升级根因，不强行切阶段 |
| 改动出错或触发安全违规 | 按步骤 5 撤销 / 回滚到上一稳定态，不带着错误继续 |
| 部署等外部操作失败 | 执行修改安全纪律的回滚路径，修复后重试 |
| 落盘提交（git 等） | 遵守 `commit-discipline.md`：原子提交、约定式 message、合并前 rebase、不强制推送共享分支 |
| 中途需暂停 / 换人 | 在 progress 写完整交接上下文（对齐 handoff 结构：From/To/阶段+断点/相关文件/依赖约束/已完成/未完成/注意/下一步），不裸退 |
